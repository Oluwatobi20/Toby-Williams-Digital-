Updated: 25 October 2026.

## Current state

- A Netlify deployment ZIP containing static website files was downloaded on 25 October 2026.
- The HTML was edited to add the Calendly consultation CTA on the homepage, Services page and Contact page.
- The user showed the new homepage CTA on the live website.
- **The actual HTML and asset files have not yet been committed to GitHub.** The repository is currently documentation-only.

## Recovery checklist
1. Download the latest published deployment files from the correct Netlify site, or recover the original editable source from the build/deploy system.
2. Inspect the ZIP locally: ensure it contains `index.html`, `services.html`, `contact.html`, other site pages, assets, `robots.txt` and `sitemap.xml`.
3. Check for sensitive information before committing (passwords, tokens, personal records, form submissions).
4. Extract the files and add the website source to a review branch in GitHub, retaining directory structure.
5. Preview the site locally and compare against the live website. Verify forms and links.
6. Check Netlify **Site configuration → Build & deploy** to determine whether it currently uses manual deploys or an existing Git repository.
7. Only after confirming the correct production source, connect this repository to Netlify if desired. Do not overwrite or disrupt the existing site accidentally.
8. Test deployment and keep a rollback route using Netlify's deployment history.

## Important caveat
A downloaded *deployed* site is not always the original editable project. If a site was generated by a framework or site builder, recover its source project separately where possible.
